# M4.11.3 设备密钥、身份验证和设备撤销

**状态：已实现。** 负责人选定 [vodozemac](https://github.com/matrix-org/vodozemac)（Apache-2.0），通过 vendored `@kinsh/vodozemac-wasm` 0.4.2 的 WASM 绑定在客户端使用。不自写 ratchet，不把私钥上传服务器。

## 已实现

1. **私钥只留在客户端**（本机 `localStorage`，键 `nova_e2ee_v1_<userId>`）。Web 存储可被页面 XSS 读取，这是已知限制，不是平台密钥库。私钥、身份密钥私钥、会话 pickle **不得**上传到 NOVA 服务器；上传接口若检测到 `pickle` / `privateKey` 等字段会拒绝。
2. **每台设备独立设备密钥。** 登录后客户端自动生成 Olm Account 并 `POST /api/e2ee/keys` 上传身份公钥与一次性预密钥、备用密钥。
3. **一次性密钥领取：** `POST /api/e2ee/keys/claim`（仅限好友）。领取后该密钥被消耗。无一次性密钥时回落备用密钥。
4. **设备撤销：** `POST /api/e2ee/devices/:id/revoke`（仅本人）。撤销后不再对外发放该设备密钥，剩余一次性密钥删除。登录会话撤销不是 E2EE 设备撤销。
5. **身份验证：** 用户可在私聊中查看**安全号码**（双方 Ed25519 身份公钥按字典序拼接后 SHA-256，编成 12 组 5 位数字，双方独立计算应一致），并可在本机标记已核对。对端身份密钥变化时给出明确提示。
6. 查阅：`GET /api/e2ee/keys`（自己）、`GET /api/e2ee/keys/:userId`（自己或好友）、`GET /api/e2ee/safety/:userId`。

## 仍由负责人决定、本步未擅自实现

- **同时在线已验证设备数量上限**（服务端仅有防滥用上限 20）。
- **密钥恢复**（丢失全部设备即无法解密历史；不提供云端可解开的备份）。
- **新设备经已有设备确认后同步历史密钥**（新设备目前只能解密加入之后发给它的消息）。

## 本步不做什么

不自写 ratchet；不把私钥放到服务器；群聊不做设备密钥分发。
