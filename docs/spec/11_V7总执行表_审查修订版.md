## 2. 固定项目基线与负责人已确认决定

### 2.1 技术基线

- 用户端以压缩包内 NOVA V5 模块化 src/ 为前端基础，经 scripts/build.mjs 构建为单 HTML。

- 后端：Node.js 22+、内置 http、node:sqlite、crypto.scrypt；当前账号数据库迁移位于 server/migrations/001_users.sql。

- 账号安全：密码使用 scrypt 加盐哈希；会话令牌只存 SHA-256 哈希；不能存储可还原密码。

- 当前数据库已有 users.vip_until（毫秒时间戳），/api/me 返回的 vip 由服务端根据到期时间计算；它还不是完整的订阅订单/权益历史系统。

- 用户端真实账号和演示数据分开存储；离线或 file:// 演示模式仍需保留。

- 实时消息第一阶段采用 SSE 服务端推送 + POST 发送；是否升级 WebSocket 以实际双向实时需求和依赖可用性为准。

- 管理端计划为独立 HTML，与用户端共用后端，但当前压缩包中尚未发现 apps/admin。

- **安全边界：** 管理员不能查看原始密码，只能重置；邮箱默认脱敏，完整查看需二次验证并记录审计；管理员邀请码一次性使用并启用 TOTP；密钥只放环境变量；支付只做占位，不接真实收款。

### 2.2 已确认产品决定（后续 AI 不得擅自改回）

1.  首阶段先给负责人本人和朋友使用，架构保持可迁移；当前不等同于已获准公开上架。

2.  动态允许图片和视频；真实上传在 M4.5 完成前，按钮不得伪装成已成功发送。

3.  **需要双向好友关系**：申请、同意、拒绝、删除；关注与好友是不同关系。私聊默认只开放给好友。

4.  **私聊要求端到端加密（E2EE）**，必须使用成熟协议实现并独立审查，禁止自创加密算法。完成之前必须清楚标记“尚未端到端加密”。群聊首版不承诺 E2EE。

5.  VIP 价格、权益可先在页面占位；支付链接留空，不接支付渠道。

6.  安全、隐私、基本聊天、好友、举报/拉黑和内容治理不得成为付费门槛。VIP 只扩展个性化和适度便利额度。
