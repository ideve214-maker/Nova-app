# M4.11.3 设备密钥、身份验证和设备撤销（待办）

**状态：待办，本步不实现。** 原因：M4.11.2 尚未选定可投入生产的协议库。按项目约定，依赖装不上时保持未加密并标明待办，**不得用自写密钥或 Web Crypto 冒充**。

## 选定库并完成许可证审查之后，必须满足

1. **私钥只留在客户端安全存储**（Web 需评估 `IndexedDB` / 非可导出 CryptoKey 的实际防护边界，并写清限制）。私钥、身份密钥、会话密钥**不得**上传到 NOVA 服务器，不得写入服务端数据库、日志或备份。
2. **每台设备独立设备密钥。** 登录账号本身不等于拥有解密密钥。
3. **新设备加入**须经已有已验证设备确认，或其它同等安全的带外验证。不能只凭登录密码自动同步全部历史密钥。
4. **设备撤销：** 用户可注销丢失的设备；撤销后该设备密钥不得再解密后续消息（前向保密由协议库提供，不自写）。
5. **身份验证：** 用户可核对手友的安全号码 / 身份指纹；密钥变化时客户端给出明确、不可轻易忽略的提示。
6. 设备数量上限与密钥恢复方案见 M4.11.1，由负责人决定后再实现。

## 当前实现

没有设备身份密钥，没有安全号码，没有设备撤销（登录会话撤销不是 E2EE 设备撤销）。界面继续「尚未端到端加密」。

## 本步不做什么

不生成密钥对，不添加 `/api/keys` 或设备预密钥接口，不把私钥放到服务器，不自写 ratchet。
