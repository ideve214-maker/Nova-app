# M4.11.5 E2EE 独立安全审查与 UI 标识

**独立安全审查尚未进行，未通过。** 因此界面**不得改成「已端到端加密」**，也不得写「独立安全审查已通过」。不宣称审查已完成。审查后仍应提供安全号码说明。

同时，M4.11.3 / M4.11.4 已用 vodozemac（Olm）实现 1:1 私聊加解密，服务端只保存密文。再写「尚未端到端加密 / 目前不是端到端加密」将与事实不符。诚实标识如下。

## 审查通过前的强制标识（当前）

- 登录后顶栏与聊天横幅：**「已登录 · 私聊使用 Olm（vodozemac）加密」**，并说明一对一私聊在发送前加密、服务端只保存密文、群聊暂不加密、独立安全审查尚未完成、请先核对手友的安全号码。Web 客户端由服务器下发，被替换的脚本可以在加密前取走明文。
- 演示模式：**「演示模式 · 未加密」**，说明不发送真实消息、也不提供端到端加密。
- 账号安全页列出加密设备与撤销，并提供安全号码入口；设置页、关于页使用同一事实。
- 不得在会话列表、消息气泡或徽章上出现「已端到端加密」标识。
- 私聊页提供「查看安全号码」；对端密钥变化时提示重新核对。

## 审查通过之后（尚未到达）

- 才可将横幅改为「已端到端加密」，并仍展示如何核对安全号码、密钥变化时的提示。
- 群聊若仍未加密，必须继续单独标明。
- Web 客户端完整性问题（服务器可下发被篡改的脚本）须写入审查范围。
