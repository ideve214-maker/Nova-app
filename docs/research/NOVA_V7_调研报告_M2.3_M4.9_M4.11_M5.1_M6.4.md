## 0. 执行摘要

1.  **NOVA VIP 建议先做单一 VIP 套餐，不做复杂多档会员。** 免费用户保留完整核心社交和安全能力；VIP 重点放在个人资料装饰、主题、专属表情、个人收藏额度和适度的内容额度扩展。建议在原型中暂用 **¥9.9/月、¥99/年** 展示，明确标注“价格测试占位，尚未开放购买”，正式价格须经负责人确认、成本核算和用户访谈后再定。

2.  **不建议把安全和基本社交功能收费。** 账号安全、私聊 E2EE、好友、举报/拉黑、基本发帖评论、基本聊天和社区管理不应成为 VIP 特权；不能按付费等级购买推荐权、消息优先级或管理员权限。

3.  **M5.1 的重点参考：** Element/Matrix 研究 E2EE 和 Spaces；Mattermost 研究频道/线程/搜索；Zulip 研究话题式组织；Rocket.Chat 研究自托管和角色/治理；Stoat（原 Revolt）研究朋友与社区聊天的产品形态。只借鉴功能思路，不直接复制受限代码。

4.  **Revolt 项目现已迁移并改名 Stoat。** 当前 GitHub 组织是 stoatchat；其后端一般采用 AGPL-3.0，个别 crate 可能使用不同许可证。不能沿用“Revolt”旧项目名而忽略当前仓库和许可证。

5.  **M4.9 先保留 SSE + POST。** SSE 是服务端到客户端单向推送，发送动作由 HTTP POST 完成；对早期消息通知足够。在线状态、输入中提示等大量双向事件明确需要时再评估 WebSocket。

6.  **M4.11 不能把“使用某个库”当作 E2EE 已完成。** Signal 体系包含 X3DH/PQXDH 和 Double Ratchet；MLS 是 IETF 标准化的群组密钥协议。Signal 官方 libsignal 虽包含 TypeScript 接口，但仓库明确说明在 Signal 产品外使用不受支持，且 API 可能变化；需额外评估维护、平台、许可证和安全审查。

7.  **中国大陆公开上线前必须做专业合规核验。** 工信部要求在境内从事互联网信息服务的 APP 主办者履行 APP 备案；《未成年人网络保护条例》对向未成年人提供信息发布、即时通讯服务的身份信息要求有明确条款；内容平台还需建立内容治理和举报处理机制。此处只做法规初查，不判断 NOVA 私人测试或未来运营模式具体适用何种义务。

## 4. M4.9：SSE 与 WebSocket 研究

### 4.1 技术区别

- **SSE（Server-Sent Events）**：服务器通过长连接向浏览器单向推送事件。浏览器端使用 EventSource 接收；客户端发消息仍通过普通 HTTP POST。适合新消息提醒、通知、状态更新和简单实时动态。

- **WebSocket**：建立双向连接，客户端和服务端都可以随时发送消息。适合输入中提示、在线状态、实时协作、频繁双向事件等。

- **Node.js 22 HTTP Server** 有 upgrade 事件可处理协议升级，但需要自行处理原始 socket 或接入受维护的 WebSocket 服务端库；不要把浏览器的 WebSocket 客户端 API误当成 Node 内置 WebSocket 服务端。

来源：[<u>MDN SSE 使用说明</u>](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)、[<u>Node.js 22 HTTP 文档</u>](https://nodejs.org/download/release/latest-jod/docs/api/http.html)。

### 4.2 NOVA 方案

**第一阶段继续 SSE + POST。** 现阶段用户规模是本人和朋友，消息发送可以 POST，服务器将新消息通过 SSE 推送给在线客户端。先解决鉴权、重连、离线补拉、幂等、心跳和连接上限。

满足下列条件时再升级 WebSocket：

- 在线状态和输入中事件需要高频双向推送；

- SSE + POST 的延迟/请求数量已经被测试证明是瓶颈；

- 需要更复杂的实时协作或持续双向同步。

升级时必须补齐：连接鉴权、心跳、断线重连、消息确认、重复消息去重、离线补拉、连接限流、服务端关闭处理、横向扩展广播方案和自动化测试。

### 4.3 一个需要特别注意的鉴权问题

当前用户端将 bearer token 存在 localStorage。浏览器原生 EventSource 没有提供任意自定义请求头配置；因此不要把 bearer token 放在 URL 查询参数中（容易进入代理/访问日志）。可选方案是：

11. 评估改为同源 HttpOnly; Secure; SameSite 会话 Cookie，并配套 CSRF 防护；或

12. 用 fetch() 读取 text/event-stream 流，以便设置 Authorization header，再自行处理重连。

该问题应纳入 M6.1 安全评估，不要到 M4.9 才临时把令牌拼进 URL。

## 5. M4.11：私聊端到端加密研究

### 5.1 术语与方案方向

**端到端加密（E2EE）** 的基本目标是：消息内容在发送端加密，只能由收件端解密，服务器主要负责传递密文；它不同于 HTTPS/TLS。HTTPS 保护客户端到服务器的传输通道，但服务器在普通 TLS 模式下仍能看到服务器端处理的消息明文。

- **Signal 体系：** Signal 官方文档列出 X3DH、PQXDH 和 Double Ratchet 等协议。Double Ratchet 在会话过程中不断派生新消息密钥，提供前向保密等安全性质，适合研究 1:1 私聊安全设计。

- **MLS：** IETF RFC 9420 标准化 Messaging Layer Security。它面向 2 到数千人的群组密钥建立，支持成员变更，并设计了前向保密与事后攻破安全等性质；更适合未来群组 E2EE 的技术评估。

- **libsignal：** Signal 的官方库提供 Java、Swift、TypeScript 等接口，但其仓库明确指出在 Signal 产品之外使用不受支持，接口/实现可能变化；当前仓库以 AGPLv3 发布。它不是“装上就自动获得完整安全聊天”的组件。

来源：[<u>Signal 技术文档</u>](https://signal.org/docs/)、[<u>Signal libsignal 仓库</u>](https://github.com/signalapp/libsignal)、[<u>IETF RFC 9420</u>](https://www.rfc-editor.org/rfc/rfc9420/)、[<u>RFC 9750 MLS 架构</u>](https://www.rfc-editor.org/rfc/rfc9750.html)。

### 5.2 对 NOVA 的建议

- 第一阶段目标仅为**双向好友之间的 1:1 私聊 E2EE**；群聊暂不承诺 E2EE。

- 不自行实现密钥交换、Ratchet、随机数、签名或加密封装。

- 协议方向先以 Signal 风格的 1:1 会话为研究对象；正式选库前检查 Web/PWA 与 iOS 的平台支持、原生桥接、库维护频率、版本升级策略和许可证。

- 每台设备应有独立设备密钥；新增设备、设备丢失、撤销设备、聊天记录迁移和密钥恢复必须在设计中处理。

- 用户应能验证好友身份/安全号码或等效身份指纹；密钥变化时给出明显提示。

- 服务端不得记录私聊明文、明文密钥或能解密密文的密钥材料。推送预览、搜索索引、日志和备份也不能泄漏明文。

- 管理端默认不可浏览私聊内容。举报流程只能在用户主动提交后，查看被举报消息及必要上下文，并写审计记录。

- 群聊如果尚未加密，界面不可暗示已加密；所有宣传文字需准确限定范围。

### 5.3 为什么必须单独安全验收

E2EE 不只是“加密函数”或数据库字段。它还涉及身份绑定、密钥轮换、设备管理、消息顺序、离线消息、重放攻击、降级攻击、附件加密、备份恢复和客户端更新信任。NOVA 当前是可构建为单 HTML 的 Web 前端；如果服务器可以随时下发被篡改的客户端代码，Web 端 E2EE 的客户端完整性也需要特别评估。

**上线门槛：** 协议库及许可证审查、跨设备测试、独立安全审查、威胁模型和界面说明均通过后，才能从“尚未端到端加密”改为“已端到端加密”。

### 6.1 APP 备案

工信部《工业和信息化部关于开展移动互联网应用程序备案工作的通知》（工信部信管〔2023〕105 号）指出，在中华人民共和国境内从事互联网信息服务的 APP 主办者，应依法履行备案手续；未履行备案手续的，不得从事 APP 互联网信息服务。文件还提到 APP 使用的域名、IP 地址等网络资源需符合相关管理要求。

官方来源：[<u>工信部 APP 备案通知</u>](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)。

### 6.2 未成年人信息与即时通讯

《未成年人网络保护条例》第三十一条明确：网络服务提供者为未成年人提供信息发布、即时通讯等服务的，应依法要求未成年人或其监护人提供未成年人真实身份信息；不提供的，不得提供相关服务。第三十二条要求不得强制未成年人同意非必要个人信息处理，不能因为拒绝非必要处理而拒绝其使用基本功能。第三十三条涉及未成年人个人信息权益保护。

《个人信息保护法》第三十一条规定，处理不满十四周岁未成年人个人信息，应取得父母或其他监护人同意，并制定专门个人信息处理规则。

官方来源：[<u>《未成年人网络保护条例》</u>](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)、[<u>《个人信息保护法》</u>](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

### 6.3 内容治理、举报和平台责任

《网络信息内容生态治理规定》要求网络信息内容服务平台履行内容管理主体责任，建立用户注册、账号管理、信息发布审核、评论审核、巡查、应急处置和违法不良信息处理等机制，并要求设置便捷投诉举报入口、及时受理处置投诉举报并反馈处理结果。若 NOVA 未来成为对公众提供 UGC 社区/即时通讯服务的平台，应由专业人士结合实际业务核实具体义务与适用范围。

官方来源：[<u>《网络信息内容生态治理规定》</u>](https://www.cac.gov.cn/2019-12/20/c_1578375159509309.htm)。

## 7. 补充技术风险：Node.js 22 与 SQLite

当前压缩包运行环境为 Node.js 22.16.0，使用 node:sqlite 时出现 ExperimentalWarning。Node 官方 Node 22 文档仍标注 node:sqlite 为 Stability 1.1（Active development），且 DatabaseSync 接口同步执行数据库操作。

对“本人和朋友的小规模试用”而言，SQLite 可以作为第一阶段轻量数据库；但正式部署前必须测试写入竞争、备份恢复、数据库文件权限、磁盘空间、同步查询阻塞和单实例限制。不能把“小范围可运行”直接等同于“适合大规模高并发”。M6.1.6 和 M6.3.3 应明确记录是否继续使用 Node 22 SQLite，或迁移至稳定驱动/独立数据库。

官方来源：[<u>Node.js v22 SQLite 文档</u>](https://nodejs.org/download/release/latest-jod/docs/api/sqlite.html)。
