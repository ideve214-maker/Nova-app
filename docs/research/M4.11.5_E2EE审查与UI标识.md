# M4.11.5 E2EE 独立安全审查与 UI 标识

**独立安全审查尚未进行，未通过。** 因此界面必须明确「尚未端到端加密」，不得改成「已端到端加密」。即使将来接入协议库，也须审查通过后才能改文案；审查后仍应提供密钥验证（安全号码）说明。

## 审查通过前的强制标识

- 登录后顶栏横幅：**「已登录 · 私聊尚未端到端加密」**，并说明消息会发到服务器，审查完成前不要发送敏感内容。
- 演示模式：**「演示模式 · 未加密」**，说明不发送真实消息、也不提供端到端加密。
- 账号安全页、关于页、设置页页脚使用同一事实，不写「即将加密」「已经保护」等模糊承诺。
- 不得在会话列表、消息气泡或徽章上出现锁形「已加密」标识。

## 审查通过之后（尚未到达）

- 才可将横幅改为已加密，并仍展示如何核对安全号码、密钥变化时的提示。
- 群聊若仍未加密，必须继续单独标明。
- Web 客户端完整性问题（服务器可下发被篡改的脚本）须写入审查范围。

## 本步做了什么

加强并统一 UI 文案；用测试锁住「必须出现尚未加密、不得出现已加密」。不宣称审查已完成，不实现加密。
