# NOVA 项目总纲（M1）

## 1 一句话目标
把现有"仅演示、不联网"的 NOVA 升级为**能联网、能聊天、功能丰富**的社交 + 聊天 + 社区 + 管理一体化平台：用户端（基础用户 / VIP）、管理端（超级管理员）、统一后端服务。美化放在功能全部完成之后统一做。

## 2 现状（来自你上传的 V2.2 文档包、V5 源码、V6 预览包与审计报告）
- V5 / V6 都是**本地演示**：数据存浏览器 localStorage，聊天不发真实消息，图片/语音按钮仅提示，无账号、无数据库、无推送。
- V5 模块化 React/TS 工程**不完整**：目录 `scr/` 与配置的 `src/` 不一致，缺 `scripts/`、`server/`、`migrations/`、认证 provider 等，**不能当作已验证可运行**。
- 已有可复用的好资产：四个底栏（首页/社区/聊天/我的）、社区角色权限表（所有者>管理员>版主>成员）、群聊角色（群主>管理员>成员）、点击音效与触觉反馈开关、页面切换动画、减少动态效果开关。
- 技术栈线索：V2.2 文档默认 Expo + React Native + TypeScript；V5 工程用 React 19 + Vite + TanStack + Zustand + Better Auth + PostgreSQL。**执行 AI 必须先让负责人在这两条路线中选一条**（推荐见第 7 节）。

## 3 版本规则冲突与裁决
旧文档（AGENTS.md、DECISIONS.md）写的是"V1 演示版：禁止后端/联网/持久化"。你现在明确要求做联网版，因此：
1. **功能禁令作废**：不再禁止后端、联网、数据库、登录。优先级按 AGENTS 原则：负责人最新指示 > 旧文档。
2. **工程纪律保留**：中文沟通；不编造测试结果；不把"代码已写"说成"已验证"；密钥不进代码；未经授权不 push、不部署、不付费；每阶段回归；版本不回退。
3. **需要负责人重新确认的旧决定**（AI 开工前必须各问一次，给推荐默认值）：
   - 帖子是否允许图片/视频（旧文档禁止；你想要"功能全覆盖"，推荐开放）。
   - 是否增加"好友"（旧文档只有单向关注；推荐：保留关注，另加可选"好友/互关"展示）。
   - 底栏仍为四项（推荐保持，避免界面拥挤）。
   - 聊天加密：旧文档把端到端加密（E2EE）定为上线硬门禁。推荐：**第一版用传输加密（HTTPS/WSS）+ 服务端加密存储，界面如实写"未端到端加密"**；E2EE 作为后续独立阶段，且必须使用成熟开源协议库并经独立审查，禁止自创算法。

## 4 安全与合规红线（对所有 AI 与开发者强制）
| 你的要求 | 本文档的处理 | 原因 |
|---|---|---|
| 管理员查看用户**原始密码** | ❌ 不实现。密码用 argon2id（或 bcrypt）加盐哈希，任何人包括创建人都无法还原。管理员可**重置密码**（生成一次性重置链接/临时码，用户首次登录强制改密） | 存明文/可还原密码属严重安全缺陷，泄露后果极重，且违反个人信息保护相关法规的安全保障义务 |
| 管理员查看注册邮箱 | ✅ 实现：默认脱敏显示（a***@x.com），点"显示完整"需二次验证并**写入审计日志** | 个人信息最小化与可追溯 |
| 超级管理员由"超级密码"设置 | ⚠️ 改为：**一次性管理员邀请码**（创建人在后台/命令行生成，有效期短、单次使用、可撤销）+ 必须开启二步验证；创建人账号为"根管理员"。超级密码本身只放服务器环境变量，不进代码、不进文档、不发给 AI | 一个共享万能密码一旦泄露，所有管理权限失守；邀请码可追溯、可撤销 |
| 管理员权限"什么都能做" | ✅ 保留全部平台管理权限，但**所有敏感操作写不可篡改审计日志**（谁、何时、对谁、做了什么、IP） | 出事能追责，也保护管理员自己 |
| 聊天内容 | 管理员默认**不可浏览私聊明文**；仅在举报流程中可查看被举报的那几条消息及上下文，并记录审计 | 隐私底线；也是未来合规的前提 |
| 未成年人、实名、备案、支付 | 标记"待专业核实"，上线前请律师/合规人员评估，AI 不下结论 | 超出 AI 能力范围 |

## 5 角色与权限模型
**平台级角色**（互斥）：
1. 基础用户（Basic）
2. VIP 用户（VIP，含到期时间；到期自动降为基础用户）
3. 超级管理员（SuperAdmin，可有多位）
4. 根管理员（Root，仅创建人；可生成/撤销管理员邀请码，可撤销其他超管）——这是对你"只有创建人知道超级密码"的安全化落地

**社区内角色**（沿用 V5）：所有者 > 管理员 > 版主 > 成员。**群聊角色**：群主 > 管理员 > 成员。
**铁律**：界面上的按钮禁用只是体验；**每个接口都必须在服务端再校验权限**（V5 的 `15_perm.js` 注释已强调这点）。

## 6 系统架构（对应你的图）
```
 用户端 App（基础/VIP）      管理端 Admin（仅超管）
            \                   /
        NOVA 统一后端服务（一个后端，两套权限域）
   API · 身份认证 · 权限控制 · 消息通信（WebSocket）· 数据服务 · 审计
            |            |           |            |
        用户数据库    消息数据库    媒体存储     安全审计
```
- 管理接口统一前缀 `/admin/*`，只接受超管令牌 + 二步验证；与用户接口彻底隔离。
- 数据库表按域拆分（用户、内容、消息、媒体、审计、配置），详见 M4。
- 实时消息用 WebSocket；离线用推送兜底。
